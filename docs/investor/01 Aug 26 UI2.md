# CAI UX Specification v1.1 (Final Freeze)

**Product:** Capital Allocation Intelligence (CAI)
**Document Type:** UI/UX Engineering Specification
**Target Audience:** Frontend Developers (React/Vue/Next.js), UI/UX Designers

## 1. Design System & Visual Language

To feel like an operating system, CAI relies on a strict design token system. Data never competes with decisions.

### 1.1 Decision State Color Palette

These colors are semantic variables. They are the *only* colors allowed to draw user attention.

* 🟢 **ADD (`var(--color-add)`):** `#10B981` (Emerald Green) - *Actionable, positive, safe.*
* 🔵 **MAINTAIN (`var(--color-maintain)`):** `#3B82F6` (Blue) - *Stable, neutral, ongoing.*
* 🟡 **ALERT (`var(--color-alert)`):** `#F59E0B` (Amber) - *Warning, pay attention.*
* 🟠 **STRUCTURE (`var(--color-structure)`):** `#F97316` (Orange) - *Caution, structural damage.*
* 🔴 **QUIT (`var(--color-quit)`):** `#EF4444` (Red) - *Terminal, immediate exit.*

### 1.2 Typography & Spacing

* **Primary UI Font:** `Inter` or `San Francisco` (Clean, highly legible sans-serif).
* **Data Font:** `Roboto Mono` or `JetBrains Mono` (Strictly used for prices, percentages, and thresholds).
* **Grid System:** 8px baseline grid (`spacing-1` = 8px, `spacing-2` = 16px, `spacing-3` = 24px).
* **Container Max-Width:** 1200px (Desktop), 100% width (Mobile).

## 2. Information Architecture & User Flows

The hierarchy is flat. We avoid deep navigation menus.

**Global Navigation Structure:**

1. **Dashboard** (Command Center)
2. **Holdings** (The Ledger)
3. **Notifications** (Actionable Deltas)

### The Daily 60-Second Workflow

The frontend must guide the user through this exact flow with zero friction.

1. **Open CAI:**
User lands directly on the Portfolio Dashboard.


2. **Address Actions Today:**
User checks the Hero widget to see exactly how many actions require attention.


3. **Review Priorities:**
User reviews the explicitly highlighted actions (e.g., "Deploy ₹50,000 to DIVIS").


4. **Analyze Stock Detail:**
User clicks the priority card to view the Decision Ladder and Explanation (Why/Why Now/What Next).


5. **Validate:**
User toggles the Fractal Analytics overlay to confirm structural levels.


6. **Execute:**
User makes the trade and closes the application.

## 3. Screen-by-Screen Layout Specifications

### Screen 1: Portfolio Dashboard (The Command Center)

**Layout:** 3-column CSS Grid on Desktop, single-column flexbox on Mobile.

* **Top Row (Hero):**
* `Actions Today` (Primary KPI): Displays immediate urgency. E.g., **"3 Actions Today"** (Sub-labels: `1 ADD`, `1 ALERT`, `1 STRUCTURE`).
* `Today's Priority Card`: Full width, highlighted with the primary action color.


* **Middle Row (Widgets):**
* `Decision Distribution Bar`: A horizontal, segmented progress bar showing the count of Holdings in [🟢 🔵 🟡 🟠 🔴].
* `Cash Available`: Highlighting deployable capital versus trapped capital.
* `Market Regime Tag`: E.g., "Market Regime: Bull" (Subtle pill component).



### Screen 2: Holdings Table

**Layout:** Standard Data Grid, ruthlessly filtered for scanning speed.

* **Default Sort:** By **Decision Priority** (QUIT -> STRUCTURE -> ALERT -> ADD -> MAINTAIN). *Never default to alphabetical.*
* **Columns:**
`Symbol` | `Decision Badge` | `Current Price` | `Next Add` | `Alert Level` | `Structure Level` | `Quit Level`
* **Styling:** Prices that are within 2% of a threshold level must stand out cleanly using bold text and a subtle colored border or a small "Near Alert" indicator badge. **Absolutely no pulsing animations.**

### Screen 3: Stock Detail & Decision Ladder

**Layout:** Split-pane design (Desktop).

* **Left Pane (Context & Narrative):**
* **Header:** Ticker, Current Price, Current State Badge, **Last Evaluated: [Timestamp]**.
* **Metrics:** `Decision Status` (Keep logic deterministic; remove any probabilistic percentages).
* **The Narrative Block:** Three distinct cards answering: *Why?*, *Why Now?*, and *What Next?*.
* **Capital Allocation:** Target vs. Current weight.


* **Right Pane (The Decision Ladder):**
* A vertical timeline-style UI component.
* Nodes represent the thresholds (Add, Alert, Structure, Quit).
* A floating "Current Price" marker dynamically positioned between the relevant nodes based on percentage distance.



### Screen 4: Fractal Analytics (UI Overlay)

**Layout:** Full-bleed chart with absolute-positioned UI overlays.

* **Visuals:** Strip away all technical indicators by default.
* **Lines:** Render solid horizontal lines mapped to `decision_thresholds`.
* **Colors:** Match the exact Design System hex codes (Green, Yellow, Orange, Red).

## 4. State Management & Accessibility

### Empty States

If no actions are required, frame this as a *success*.

* **Copy:** "No portfolio actions required today. All positions remain healthy. Next automated review: Friday Close."

### Loading & Error States

* **No generic spinners.** Use Skeleton Loaders that mimic the exact shape of the data.
* If the Decision Engine times out, fallback to cached data and display a prominent warning banner: *"Displaying data as of [Timestamp]. Live evaluation is currently reconnecting."*

### Accessibility (a11y)

* **Color Independence:** Never rely *only* on color. Every colored state must be accompanied by text (e.g., the word "ALERT").
* **Screen Readers:** Use `aria-labels` for the Decision Ladder so screen readers read it as a logical sequence: *"Current price is 8,050. Next Add level is 8,250. Alert level is 7,900."*
