# Feature Request — Bear vs Bull Debate in GuidanceCheck & Expansion Lens

**Date:** 2026-06-19
**Status:** DRAFT — awaiting user approval before execution
**Author:** Lead AI Engineer (Kimchi)
**Target consumers:** Immanuel Santosh (Digital Twin) + the 149-universe Expansion Lens users

---

## Problem

Today, the MRI platform has **two parallel bear/bull debate engines** that are used in specific, narrow contexts:

| Engine | Location | Used by | Context |
|---|---|---|---|
| `engine_qualitative.debate.run_debate()` | `engine_qualitative/debate.py` (10K) | PERX (`engine_perx/orchestrator.py:45`) | Long-form bull/bear/mistakes/verdict, fired on demand with `include_debate=true` flag |
| `engine_fundamental.ForensicDebateEngine.run_bear_layer()` / `run_bull_layer()` | `engine_fundamental/forensic_debate.py` (5.5K) | AAE V3 (`engine_fundamental/aae_orchestrator.py`) | 5-bullet bull + 5-bullet bear in `legacy_forensic.layers.{bull_case,bear_case}` |

Neither engine is **reachable from GuidanceCheck** (the management-integrity surface) or from **Expansion Lens** (the PE-rerating surface). The user has to manually compare their own numbers across the 7 QIF agents, the intonation trajectory, the credibility verdict, the PE categories, and the cross-check matrix — then mentally argue both sides.

**What the user is asking for:** a bear agent and a bull agent fight it out, **inside each of those two reports**, with the output visibly rendered. The user should be able to read POLYCAB's Expansion Lens report and see "here's the strongest bull case, here's the strongest bear case, here's how the data weights each."

---

## Goal

Add a **per-context bear vs bull debate** that fires on demand from both:

1. **GuidanceCheck** — the management-integrity detail view for any symbol
2. **Expansion Lens** — the per-symbol Expansion Lens report (alongside the existing Bottom Line + cross-check)

Each debate presents two clearly-labeled arguments (Bear, Bull) generated by an LLM grounded in **the same data the user is already looking at in that report**. No separate score table, no second source of truth.

---

## Scope

### IN

- New isolated module `engine_debate/` (mirrors `engine_guidance/` pattern from Decision 094)
- Domain-specific prompt templates for GuidanceCheck context and Expansion Lens context
- Shared bear/bull scaffolding — one `run_debate(symbol, context_kind, context_data)` entry point
- Per-context LLM calls (~2 per debate, ~$0.002 total at gpt-4o-mini rates)
- Optional third "adjudicator" call that picks a winner with reasoning (~+$0.001, opt-in)
- Caching: debate results stored in a new `conviction_debates` table, keyed by `(symbol, context_kind, context_hash)`. Re-opening a report = 0 LLM cost, instant render.
- Two API endpoints:
  - `POST /api/guidance/{symbol}/debate` (fires + persists; returns full debate JSON)
  - `POST /api/pe-expansion/{symbol}/debate` (same shape)
- Frontend: a "Run Debate" / "Bear vs Bull" affordance in both reports
  - GuidanceCheck: button in the report header, opens a debate modal
  - Expansion Lens: new "Bear vs Bull" section at the bottom of the report, below the existing Footer; same modal pattern
- Tests: prompt rendering, cache hit/miss, API endpoints

### OUT

- **Not** a replacement for the existing AAE V3 forensic debate — that one is part of the master_score and lives in its own lane
- **Not** a real-time / streaming debate (current extraction is batch, this stays batch)
- **Not** a debate over a transcript itself — the bear/bull argue the **report's quantitative verdict**, not the original transcript language
- **Not** a multi-round debate (one bear + one bull + optional adjudicator = three turns max)
- **Not** auto-fired on every report load — on-demand only, to respect LLM cost + latency

## Design Overview

### Module shape

```
engine_debate/
├── __init__.py
├── debate_engine.py          # main entry: run_debate(symbol, context_kind, context_data)
├── prompts_guidance.py       # bear/bull prompt builders for GuidanceCheck context
├── prompts_pe_expansion.py   # bear/bull prompt builders for Expansion Lens context
├── adjudicator.py            # optional third-turn "verdict" generator
└── cache.py                  # convinction_debates read/write helpers

api/guidance.py               # + POST /api/guidance/{symbol}/debate
api/pe_expansion.py           # + POST /api/pe-expansion/{symbol}/debate
migrations/004_debate_cache.sql  # conviction_debates table
frontend/src/DebateModal.tsx  # shared debate renderer (bear / bull / verdict stack)
frontend/src/GuidanceCheck.tsx     # + Run Debate button
frontend/src/PeExpansionReport.tsx # + Bear vs Bull section
tests/test_debate_engine.py
```

### Context payload shape (per debate kind)

For **GuidanceCheck** (`context_kind="guidance"`):

```python
{
  "symbol": "POLYCAB",
  "credibility": {accuracy_pct, verdict_zone, trend, consecutive_miss_quarters,
                  lag_score, achieved_count, missed_count, total_promises,
                  summary, narrative_assessment},
  "intonation": {latest, previous, quarter_over_quarter_delta, tone_shift_dimensions,
                 timeline (last 4 quarters)},
  "verifier_summary": {n_total, n_achieved, n_missed, n_partial, n_unable,
                       unable_reasons breakdown},
  "guidance_quality_signal": "DIRECTIONAL ONLY | MIXED | NUMERICAL",
}
```

For **Expansion Lens** (`context_kind="pe_expansion"`):

```python
{
  "symbol": "POLYCAB",
  "bottom_line": {summary, action, highlights},
  "pe_score": 83.6, "bucket": "Strong", "rank": 3, "total": 149,
  "top_drivers": [...],
  "cross_check": [...],  # 5-dimension alignment matrix
  "independent_check": {master_score, reasons},
  "financial_quality": {score, category, agents},
  "price_action": {total_score, breakout_state, conditions},
  "credibility": {...},   # same shape as GuidanceCheck
}
```

### Debate flow

1. User clicks "Run Debate" in either report
2. Frontend calls `POST /api/{kind}/{symbol}/debate`
3. Backend assembles context payload from DB (deterministic SQL — no LLM)
4. Cache check: hash the context payload, look up `conviction_debates` for a hit
   - **Hit** → return cached bear/bull/adjudicator instantly
   - **Miss** → fire bear LLM call + bull LLM call (sequential, ~5-10s wall)
   - Optionally fire adjudicator (~+3-5s)
5. Persist to `conviction_debates` with the context_hash
6. Return JSON: `{bear: str, bull: str, adjudicator: str|null, generated_at, cached: bool}`

### UX

- **GuidanceCheck**: small "🗣️ Run Debate" button in the page header next to the symbol name. Opens `DebateModal` showing bear (red-tinted card) + bull (green-tinted card) + optional adjudicator (gold-tinted card). Each card shows the LLM output verbatim, with timestamp + "regenerate" link.
- **Expansion Lens**: new section at the bottom of the report (above the existing footer disclaimer) titled "🗣️ Bear vs Bull". Same modal pattern. Shows the same context the user just read above — so the debate argument is grounded in numbers they can verify.

### Caching strategy

- Key: `sha256(json.dumps(context_payload, sort_keys=True))` — deterministic, re-debates only when underlying data changes
- TTL: none. A debate is a snapshot of what the data said at that moment. If data changes (new quarter ingested, new credibility row), the context hash changes → cache miss → re-debate.
- Storage: full context payload + bear + bull + adjudicator + generated_at in one row per `(symbol, context_kind, context_hash)`.

### Cost & latency

| Operation | LLM calls | Wall time | Cost (gpt-4o-mini) |
|---|---|---|---|
| First-time debate | 2 (bear + bull) | ~6-10s | ~$0.002 |
| With adjudicator | 3 | ~10-15s | ~$0.003 |
| Cache hit | 0 | <100ms | $0 |
| Backfill 149 symbols × 2 kinds | ~596 calls | ~60 min | ~$0.60 one-time |
| Backfill 149 × 2 + adjudicator | ~894 calls | ~90 min | ~$0.90 one-time |

## Open Questions for User

1. **Adjudicator default**: ship with adjudicator ON (always 3 calls) or OFF (default 2 calls, user opts in)? Default proposal: **OFF**, with a checkbox in the UI.
2. **Auto-include in Expansion Lens email**: when the user emails the Expansion Lens report, should the bear/bull be appended as a new section? Default proposal: **NO**, debate is on-demand only.
3. **Caching aggressiveness**: should we backfill debates for the top-20 Expansion Lens symbols at engine-persist time so the top-N panel can include "Bear says… / Bull says…" mini-previews? Default proposal: **NO**, backfill is opt-in via a CLI flag. Top-N panel stays as-is.
4. **Naming**: `engine_debate/` or `engine_bear_bull/` or `engine_adversarial/`? Default proposal: **`engine_debate/`** (shortest, clearest).

---

## What This Is NOT

- **Not** a replacement for the existing AAE V3 forensic debate. That one is tied to the 8-layer master_score and fires automatically. This new one is on-demand, per-context, and lives in its own lane.
- **Not** a replacement for the existing PERX `include_debate=true` flow. PERX keeps its longer-form `mistakes + verdict` debate; this new engine is "show me the bear case and the bull case side-by-side, fast."
- **Not** a route into LLM-driven portfolio advice. Both prompts are explicitly grounded in the deterministic context payload and explicitly instructed to argue from the data, not invent new claims.
